# 菜单与权限管理设计

## 目标

在已有全局菜单树和租户内角色授权之上，补齐目录、页面菜单和按钮权限的查询、创建、更新、启停、删除及前端维护页面。

## 领域边界

`sys_menu` 是全平台共享资源，不携带 `tenant_id`。节点层级固定为：目录可包含目录或页面菜单，页面菜单可包含按钮权限，按钮权限不能包含子节点。页面菜单必须配置路由和组件，按钮必须配置唯一的 `领域:资源:动作` 权限码且不作为可见菜单。

所有 V2/V5 初始化节点标记为内置。内置节点允许调整名称、图标、排序和可见性，但不可改变父节点、类型、路由、组件和权限码，也不可停用或删除。自定义节点存在子节点或有效角色关联时不可删除，启用节点前要求父节点已启用。

## 授权与会话一致性

菜单写接口分别使用 `system:menu:create/update/enable/disable/delete`，管理树和详情分别使用 `system:menu:list/detail`。现有 `TENANT_ADMIN` 自动拥有全部启用按钮权限，因此具备菜单写权限的租户管理员修改的是全平台资源；部署时应只把这些权限交给受信管理员。

按钮权限语义发生变化时，通过显式跨租户联表查询定位直接获权用户与租户管理员，在各自租户作用域内递增 `auth_version`，事务提交后再尽力撤销 Redis 会话。数据库版本校验是 Redis 暂时不可用时的安全兜底。

## 数据库与接口

V5 为 `sys_menu` 增加 `built_in`，保护固定菜单并新增菜单管理页面及 7 个权限码。升级时递增现有用户认证版本，避免旧会话缺少新权限快照。

管理接口位于 `/api/v1/system/menus`，提供 `management-tree`、详情、创建、更新、启用、停用和删除；原有只读 `tree` 与 `permissions` 接口保持兼容。所有 HTTP 菜单 ID 继续使用字符串，避免 JavaScript 数值精度丢失。

## 验收

- Flyway 可从空库连续执行五版迁移；
- 菜单字段、层级、循环引用、内置保护及删除约束均有服务测试；
- 跨租户角色关联和受影响用户定位由真实 Mapper XML 集成测试覆盖；
- 前端通过权限路由与按钮权限控制菜单管理入口和操作，并通过类型化表单提前校验配置；
- 后端 Maven 全量测试、前端 ESLint、类型检查和生产构建必须全部通过。
