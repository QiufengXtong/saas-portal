# 前端 IAM 管理闭环设计

## 1. 阶段目标

本阶段将现有极简启动页升级为可实际使用的租户管理后台，覆盖登录、会话恢复、退出、后台布局、权限路由、用户管理、角色管理和菜单授权。

## 2. 技术与安全约束

- 延续 Vue 3、TypeScript、Vite、Pinia、Vue Router、Axios 和 Element Plus，不新增 UI 框架。
- Access Token 与 Refresh Token 保存到 `sessionStorage`，关闭标签页后清除；请求层统一附加 Bearer Token。
- 遇到 401 时仅允许一个刷新请求，成功后重放等待请求；刷新失败时清空会话并跳转登录页。
- 路由和按钮同时按后端 `/auth/me` 返回的权限集合控制，但后端授权仍是最终安全边界。
- 所有 HTTP 调用进入 `src/api`，页面不直接使用 Axios。

## 3. 页面范围

- `/login`：租户编码、用户名、密码登录。
- `/dashboard`：当前租户和用户概览。
- `/system/users`：分页筛选、创建、编辑、启停、重置密码、删除和分配角色。
- `/system/roles`：分页筛选、创建、编辑、启停、删除和分配菜单。
- 后台布局：侧栏、顶栏、当前用户、退出和响应式窄屏导航。

## 4. 后端契约补充

新增 `GET /api/v1/system/roles/{id}/menus`，返回该角色当前菜单 ID 字符串列表，并复用 `system:role:detail` 权限。原因是菜单授权采用整体替换语义，编辑前必须加载已有集合。

## 5. 验收标准

1. 未登录用户只能访问登录页，登录后可恢复当前用户和权限。
2. Access Token 过期后可原子刷新并重放请求，刷新失败回到登录页。
3. 用户与角色页面覆盖后端现有管理能力，所有危险操作均二次确认并防重复提交。
4. 无权限菜单和按钮不展示，直接访问无权限路由进入 403 页面。
5. 前端 lint、类型检查和生产构建通过，后端全模块测试与打包通过。
